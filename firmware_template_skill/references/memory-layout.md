# memory.x layout rules

Generated by `build_layout()` / `render_memory_x()` in `scripts/bedrock_gen.py`.

## Flash partitioning

Flash is treated as a list of erase sectors (all flash banks merged; must be consecutive, otherwise the
script aborts). Sector sizes may differ (F4 has 16K/64K/128K sectors).

Order from flash base:

| region | size | present when |
|---|---|---|
| `BOOT2` | 0x100 | rp2040 only (second-stage bootloader from embassy-rp `boot2-*` feature, placed via `link-rp.x`) |
| `BOOTLOADER` | `--min-bootloader` (24K) rounded up to whole sectors | `--bootloader` |
| `BOOTLOADER_STATE` | 1 sector | `--bootloader` |
| `FLASH` (application) | largest A such that DFU ≥ A + one sector | always |
| `BOOTLOADER_DFU` | rest minus CONFIG | `--bootloader` |
| `CONFIG` | 1 sector (the last one) | `--config-page` |
| `FREE_FLASH` | leftover (commented out) | never with current algorithm, kept for manual edits |

Dual-bank STM32 (`BANK_2` present): if it does not cost application space, DFU is aligned to the start
of bank 2 (allows bank-swap-less updates while executing from bank 1).

Without `--bootloader`/`--config-page` the whole flash is `FLASH` (minus BOOT2 on rp2040).

## Symbols

For every non-`FLASH`, non-main-RAM region: `__<name>_start` / `__<name>_end`.

Flash partition symbols are **offsets from the flash base** (`- ORIGIN(BOOTLOADER)` / `- ORIGIN(BOOT2)` /
`- ORIGIN(FLASH)`), because embassy-boot `FirmwareUpdaterConfig::from_linkerfile_blocking` and the
embassy flash drivers use offsets, not absolute addresses. nRF flash starts at 0, so no shift there.

The bootloader `memory.x` is the same table with renames: `BOOTLOADER→FLASH`, app `FLASH→BOOTLOADER_ACTIVE`,
extra RAM banks / `CONFIG` / `BKP_REGS` dropped. embassy-boot's `BootLoaderConfig::from_linkerfile_blocking`
reads `__bootloader_active_start/end`, `__bootloader_dfu_start/end`, `__bootloader_state_start/end`.

## RAM

Main RAM (exported as `RAM` for cortex-m-rt's `link.x`): `--main-ram`, else `AXISRAM` (H7: avoids DTCM DMA
restrictions), else a region named `RAM`/`SRAM`, else the largest one except ITCM.

Every other RAM bank gets a `NOLOAD` output section `.<name>` collecting `.<name>` and `.<name>.*` input
sections plus the symbols above; `src/init_ram.rs` enables its RCC clock (bits found by matching
`<NAME>EN` fields in RCC `*ENR` registers, H7 gets both `AHBxENR` and `C1_AHBxENR`) and zeroes it at boot.
Place data with `#[unsafe(link_section = ".sram2")] static mut BUF: [u8; N] = [0; N];`.
RP2350 `SRAM8/9` are direct-mapped (non-striped) banks, useful for per-core stacks.

Notes for manual edits: the cortex-m-rt `link.x` requires `FLASH` and `RAM`; `--nmagic` is passed so
regions need not be 64K-aligned; `flip-link` moves the stack below `.bss/.data` for overflow detection.

## Backup-register counters (`BKP_REGS`)

With `--bkp-counters tamp|rtc|auto` a pseudo memory region `BKP_REGS` is added at the `BKPR` register array
of TAMP (G0/G4/H5/L5/U5/WB/WL) or RTC (F0/F2/F3/F4/F7/H7/L0/L1/L4). The `.bss._CNT_BKP_BUFFER` input section
of the `cnt` crate is redirected there, and `CNT_BKP_BUFFER_SIZE_WORDS` in `.cargo/config.toml` is set to the
number of registers (5 on G0, 32 on H7/L4/...). Startup code does not zero it, and it survives resets (with
VBAT also power loss). The F1 `BKP` peripheral has non-contiguous 16-bit registers and is not supported.

Write access needs `PWR.DBP=1` (+ PWR clock, + RTC APB clock on some parts) — `src/init.rs::enable_backup_registers()`
does that from stm32-data register info; it purposely does **not** reset the backup domain in that case.

## ESP32

No `memory.x`: esp-hal ships `linkall.x` (must be the last `-T` argument) and the esp-idf bootloader partition
table governs OTA. `--bootloader`/`--config-page` are rejected for ESP. Use `esp-storage` + the esp-idf
partition table for persistent data.
